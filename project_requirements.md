Iată textul complet extras din documentul atașat: SOFTWARE ENGINEERING | DEVELOPMENT OF SECURE APPLICATIONS DEVELOPMENT OF SECURE APPLICATIONS (DSA) Dezvoltarea aplicațiilor securizate (DAS) PBL PROJECT DEVELOPMENT | INTERNSHIP GUIDELINES Project Description This semester's PBL project centers on creating a secure application. Students will integrate security practices throughout the development lifecycle, ensuring the application is resilient against cyber threats. During the one-month internship in September, students will work in teams with company mentors to define and begin developing a realistic Minimum Viable Product (MVP). The purpose of September is to establish the project foundation. DAS will continue from October to December at university. Project Objectives Security Integration: Embed security measures at every development stage. Mitigate Vulnerabilities: Address common vulnerabilities in frontend, backend, and database management. Compliance: Adhere to industry security standards and regulations. Incident Response: Develop skills in detecting and responding to security incidents. Technical Requirements 1. Encryption and Authentication Implement strong encryption algorithms for data at rest and in transit. Use multi-factor authentication (MFA) to enhance user security. Ensure secure password storage using hashing algorithms. 2. Secure APIs Validate all inputs to prevent injection attacks. Use OAuth 2.0 for secure API authentication and authorization. Ensure proper error handling to avoid exposing sensitive information. 3. Frontend Security Mitigate Cross-Site Scripting (XSS) by escaping all user inputs and using Content Security Policy (CSP). Prevent Cross-Site Request Forgery (CSRF) using anti-CSRF tokens. Implement secure cookie attributes (HttpOnly, Secure, SameSite). 4. Backend Security Prevent SQL Injection by using parameterized queries and ORM frameworks. Secure session management and ensure proper timeout and invalidation mechanisms. Regularly update and patch server software to close known vulnerabilities. 5. Database Management Use encryption for sensitive data storage. Implement role-based access control (RBAC) to limit data access. Ensure secure backup and recovery processes. Expected Outcomes Secure Application: A secure application, may not be fully functional, though students should be able to thoroughly describe the security aspects they considered in their projects and display a clear understanding of security vulnerabilities in software development. Security Documentation: Comprehensive documentation of security measures, threat models, and risk assessments. Incident Response Plan: A detailed plan for responding to security incidents. Final Presentation: Demonstration and discussion of the application's security features and development challenges. Actions for Students Security Requirement Analysis: Identify and document the security requirements specific to the application; analyze potential threats and vulnerabilities during the planning phase. Design: Develop a design plan that integrates security principles, focusing on secure architecture, data protection, and access control; design threat mitigation strategies, including encryption, authentication, and authorization mechanisms. Implementation of Security Measures: Write code that incorporates security practices, such as input validation, secure coding techniques, and proper error handling; implement encryption for sensitive data both at rest and in transit. Documentation: Maintain thorough documentation covering all security measures, threat models, and risk assessments; document security decisions and the processes used to secure the application. Final Presentation: Prepare and deliver a presentation focusing on the security aspects of the application, the challenges encountered, and the demonstration of the security features implemented. Work During the September Internship During September, students should work together with their company mentors on the following activities: MVP Idea: Choose a realistic project idea that can be extended after the internship. Domain and Security Analysis: Analyze the application domain and identify the main security risks relevant to the project. Architecture and Technologies: Choose appropriate technologies, define the application architecture, and organize the project structure. Security Priorities: Decide which security measures are necessary for the first MVP and which can be implemented later. Core Implementation: Begin implementing the essential functionality of the application. Basic Security Controls: Implement several important security measures appropriate for the selected project. Possible Security Measures Depending on the project, security measures may include: 1. Authentication and Access Control Secure authentication and authorization. Two-Factor Authentication (2FA). Secure password hashing and password policies. Role-based access control (RBAC). Brute-force protection. 2. API and Session Security API rate limiting and API access control. Secure JWT or session management. Secure error handling. 3. Input and Application Security Input validation and sanitization. Protection against SQL Injection, XSS, CSRF, IDOR, and privilege escalation. CAPTCHA protection against bots. Secure file upload and download mechanisms. 4. Data and Monitoring Encryption of sensitive information. Security logging and monitoring. Students are not expected to implement all security mechanisms during September. The team and mentor should select the protections that are most important for the first version of the MVP and plan the remaining improvements for October to December. Security Measure Explanation For each security measure selected for the project, students should be able to explain: Security Problem: What security problem or attack the measure addresses. Relevance: Why the problem could be relevant to their application. Implementation: How the security measure was implemented. Testing: How they tested whether the protection works. Limitations: What limitations remain and what could be improved later. Role of Company Mentors Company mentors should guide the teams during September by helping them understand realistic risks for the selected project, recommending suitable approaches or technologies, and giving practical examples of how similar security concerns are handled in real software projects. Expected Outcomes by the End of September Project Definition: A clearly defined project idea and scope. Initial MVP: A first working version containing the essential functionality. Security Analysis: A basic analysis of the main risks and security requirements. Basic Security Measures: Several prioritized security controls implemented and tested. Development Plan: A clear plan for the work and security improvements to be completed from October to December. Traducerea integrală în limba românăINGINERIA PROGRAMĂRII | DEZVOLTAREA APLICAȚIILOR SECURIZATE (DAS) GHIDUL PROIECTULUI PBL | STAGIUL DE PRACTICĂ Descrierea proiectului Proiectul PBL din acest semestru se concentrează pe crearea unei aplicații securizate. Studenții vor integra practici de securitate pe parcursul întregului ciclu de viață al dezvoltării, asigurându-se că aplicația este rezistentă la amenințările cibernetice. În timpul stagiului de practică de o lună din septembrie, studenții vor lucra în echipe alături de mentori din companii pentru a defini și începe dezvoltarea unui Produs Minim Viabil (MVP) realist. Scopul lunii septembrie este de a pune bazele proiectului. Cursul DAS va continua din octombrie până în decembrie la universitate. Obiectivele proiectului Integrarea securității: Încorporarea măsurilor de securitate în fiecare etapă de dezvoltare. Atenuarea vulnerabilităților: Abordarea vulnerabilităților comune la nivel de frontend, backend și gestionare a bazelor de date. Conformitate: Respectarea standardelor și reglementărilor de securitate din industrie. Răspuns la incidente: Dezvoltarea abilităților de detectare și răspuns la incidentele de securitate. Cerințe tehnice Criptare și Autentificare Implementarea unor algoritmi puternici de criptare pentru datele stocate (at rest) și în tranzit. Utilizarea autentificării multifactor (MFA) pentru creșterea securității utilizatorilor. Asigurarea stocării securizate a parolelor folosind algoritmi de hashing. API-uri Securizate Validarea tuturor intrărilor pentru a preveni atacurile de tip injection. Utilizarea OAuth 2.0 pentru autentificarea și autorizarea securizată a API-urilor. Gestionarea corespunzătoare a erorilor pentru a evita expunerea informațiilor sensibile. Securitate Frontend Prevenirea Cross-Site Scripting (XSS) prin filtrarea (escaping) tuturor intrărilor de la utilizatori și prin utilizarea Content Security Policy (CSP). Prevenirea Cross-Site Request Forgery (CSRF) prin utilizarea token-urilor anti-CSRF. Implementarea atributelor securizate pentru cookie-uri (HttpOnly, Secure, SameSite). Securitate Backend Prevenirea SQL Injection prin utilizarea interogărilor parametrizate și a framework-urilor ORM. Gestionarea securizată a sesiunilor, cu mecanisme adecvate de expirare (timeout) și invalidare. Actualizarea și aplicarea periodică a patch-urilor pe software-ul serverului pentru închiderea vulnerabilităților cunoscute. Gestionarea Bazelor de Date Criptarea stocării datelor sensibile. Implementarea controlului accesului bazat pe roluri (RBAC) pentru limitarea accesului la date. Asigurarea proceselor sigure de backup și recuperare a datelor. Rezultate așteptate Aplicație Securizată: O aplicație securizată, care poate să nu fie complet funcțională, dar studenții trebuie să poată descrie amănunțit aspectele de securitate luate în calcul și să demonstreze o înțelegere clară a vulnerabilităților de securitate. Documentație de Securitate: Documentație cuprinzătoare privind măsurile de securitate, modelele de amenințări (threat models) și evaluările de risc. Plan de Răspuns la Incidente: Un plan detaliat pentru reacția în caz de incidente de securitate. Prezentare Finală: Demonstrarea și discutarea funcționalităților de securitate ale aplicației și a provocărilor apărute pe durata dezvoltării. Acțiuni pentru studenți Analiza cerințelor de securitate: Identificarea și documentarea cerințelor de securitate specifice aplicației; analizarea potențialelor amenințări și vulnerabilități în faza de planificare. Proiectare (Design): Elaborarea unui plan de proiectare care integrează principiile de securitate (arhitectură sigură, protecția datelor, controlul accesului, mecanisme de criptare, autentificare și autorizare). Implementarea măsurilor de securitate: Scrierea codului integrând bune practici de securitate (validarea intrărilor, tehnici de codare securizată, gestionarea adecvată a erorilor, criptarea datelor sensibile). Documentație: Menținerea unei documentații detaliate pentru toate măsurile de securitate, modelele de amenințări, evaluările de risc și deciziile arhitecturale luate. Prezentare finală: Pregătirea și susținerea unei prezentări axate pe securitatea aplicației, provocările întâmpinate și demonstrarea măsurilor implementate. Activitatea din timpul stagiului din septembrie Studenții vor colabora cu mentorii din companii pentru: Ideea de MVP: Alegerea unei idei realiste de proiect, care poate fi extinsă după internship. Analiza domeniului și a securității: Analizarea domeniului aplicației și identificarea principalelor riscuri de securitate. Arhitectură și tehnologii: Alegerea tehnologiilor potrivite, definirea arhitecturii și organizarea structurii proiectului. Priorități de securitate: Stabilirea măsurilor de securitate necesare pentru primul MVP și a celor ce pot fi amânate. Implementarea de bază: Începerea dezvoltării funcționalităților esențiale. Controale de bază de securitate: Implementarea câtorva măsuri cheie adecvate pentru proiectul selectat. Măsuri posibile de securitate Autentificare și controlul accesului: autentificare/autorizare sigură, 2FA, politici și hashing sigur pentru parole, RBAC, protecție împotriva atacurilor brute-force. Securitatea API-urilor și a sesiunilor: rate limiting, controlul accesului la API, management securizat al sesiunilor/JWT, tratarea sigură a erorilor. Securitatea aplicației și a intrărilor: validare și sanitizare, protecție contra SQL Injection, XSS, CSRF, IDOR, privilege escalation, protecție CAPTCHA, încărcare/descărcare sigură de fișiere. Date și monitorizare: criptarea informațiilor confidențiale, logging de securitate și monitorizare. (Studenții nu sunt obligați să implementeze toate aceste mecanisme în luna septembrie; măsurile prioritare sunt alese împreună cu mentorul). Explicarea măsurilor de securitate Pentru fiecare măsură aleasă, studenții trebuie să poată explica: Problema de securitate: Ce atac sau problemă rezolvă. Relevanța: De ce este importantă pentru aplicație. Implementarea: Cum a fost realizată din punct de vedere tehnic. Testarea: Cum a fost verificată eficiența protecției. Limitările: Ce limitări există și ce poate fi îmbunătățit ulterior. Rolul mentorilor din companii Mentorii ghidează echipele ajutându-le să înțeleagă riscurile reale, recomandând abordări și tehnologii potrivite și oferind exemple practice din proiecte software reale. Rezultate așteptate la sfârșitul lunii septembrie Definirea proiectului: O idee și o sferă de aplicare clar definite. MVP Inițial: O primă versiune funcțională cu funcționalitățile de bază. Analiza de securitate: O analiză preliminară a riscurilor principale și a cerințelor de securitate. Măsuri de bază de securitate: Câteva măsuri prioritare implementate și testate. Plan de dezvoltare: Un plan clar pentru continuarea dezvoltării și a îmbunătățirilor de securitate în perioada octombrie – decembrie
